# [FEAT] Commandパターンによるユーザー操作履歴の抽象化とデバッグ用シリアライズ対応 (ID: 009)

## 1. 概要 / Summary
バグの再現性向上、ユーザー操作の解析、および自動操作デモの実行を目的として、ユーザーが行う主要な操作（本のロード、ページめくり、表示カスタマイズ設定の変更、デバッグ操作等）を Command パターンに基づき抽象化し、実行履歴を追跡・制御します。
実行されたコマンドは時系列順に履歴リストに蓄積され、JSON 等のテキスト形式へ相互にシリアライズできるようにします。これにより、デバッグメニューから現在の操作履歴をエクスポートしたり、過去の操作ログ（JSON）を入力して一連の操作を完全に再実行・再現（リプレイ）することが可能になります。
履歴の世代数は最大100世代（FIFO破棄。ただし書籍初期ロードコマンドは固定保護）に制限し、シリアライズデータ量やメモリの肥大化を防ぎます。

## 4. 実装方針 / Implementation Plan
Target Branch: `feat/009-command-pattern-history`

### 4.1 コマンド構造と具象クラスの設計
1. **`Command` (基底クラス)**:
   - `constructor(type)`
   - `execute()`: アプリケーション側のレシーバーを制御し状態を更新する抽象メソッド。
   - `toJSON()`: シリアライズ用のプレーンオブジェクト（`{ type, params }`）を返す。
2. **`LoadBookCommand` (具象クラス)**:
   - パラメータ: `fileName`, `fileContent`
   - `execute()`: `currentFileName = fileName`, `currentFileContent = fileContent` を設定し、`displayBook()` を呼び出す。
   - **セキュリティ**: インポートデータとして悪意あるスクリプトが挿入された場合に備え、`fileName` の DOM レンダリング時（ヘッダー部タイトル）には必ず `textContent` を使用し、本文挿入前にはサニタイズ処理（`sanitizeDOM`）を通してパースした結果（`parsed.body`）を適用する。
3. **`NavigatePageCommand` (具象クラス)**:
   - パラメータ: `targetPage` (1〜N)
   - `execute()`: 指定された論理ページ番号へスクロール。ビューポート幅と送り方向（RTL/LTR）から正確なスクロール位置を算出し適用する。
4. **`UpdateConfigCommand` (具象クラス)**:
   - パラメータ: `configKey` (theme, font, size, line-height, etc.), `configValue`
   - `execute()`: UI設定状態を更新し、対応する DOM クラスの更新やイベント発火を行う。
5. **`SyncBookmarkCommand` (具象クラス)**:
   - パラメータ: `progress`
   - `execute()`: localStorage へしおりデータを保存・適用。

### 4.2 コマンドマネージャ (`CommandManager`) の設計
- `commandHistory = []` 配列で履歴を保持。
- **履歴世代数の制限ロジック**:
  - コマンド実行時に履歴にプッシュするが、`commandHistory.length > 100` になった場合、FIFO（先入れ先出し）で古いコマンドから破棄する。
  - ただし、再現時の初期ロード状態を担保するため、インデックス `0` にある最初の `LoadBookCommand` は自動破棄から除外し、常に先頭に保護・固定する。
- **エクスポート/インポートインターフェース**:
  - `exportJSON()`: `commandHistory` 内の全コマンドをオブジェクト配列として `JSON.stringify` する。
  - `importJSON(jsonString)`: `JSON.parse` し、各オブジェクトの `type` に応じて具象コマンドインスタンスを逆シリアライズ復元する。
  - **セキュリティ**: `JSON.parse` 呼び出し時は必ず `try-catch` で囲み、構文エラー時にはアプリのクラッシュを防いでデバッグUI上にエラーダイアログを表示する。

### 4.3 リプレイ（自動再生）実行フロー
- `replay(history)`: インポートされたコマンドを順に実行。
- スムーズスクロールや初期パースのレンダリング遅延を考慮するため、各コマンドの実行を `300ms` のインターバルを持つ非同期ループ（`setTimeout` または async/await によるプロミス制御）で実行し、描画と表示同期が完全に完了してから次の操作へ進む。

### 4.4 デバッグUIへの追加およびPCキーバインド
- デバッグ画面（`#debug-modal`）内に、「操作履歴 (JSON)」テキストエリア、および「コピー (エクスポート)」ボタン、「リプレイ (インポート)」ボタンを配備。
- インラインスタイルを排除し、`style.css` に準拠したスタイルクラスを適用。
- **PCのキーバインド対応**:
  キーボードショートカット **`Ctrl + Shift + H`**（HistoryのH）が押下された際、デバッグ画面が開いていなくても、現在の操作履歴 JSON を自動的にクリップボードにエクスポート（コピー）し、画面上に「操作履歴をクリップボードにコピーしました」という一時的な通知（トーストUI）を表示する。

## 5. 完了条件 / Success Criteria (DoD)
- [ ] ユーザーの「本ロード」「設定切り替え」「ページ送り」「しおり同期」が、100世代以内でシリアライズ可能なコマンドとして蓄積されること。
- [ ] デバッグ画面から操作履歴を JSON としてエクスポート（コピー）できること。
- [ ] PCのキーバインド **`Ctrl + Shift + H`** を押下した際に、デバッグ画面の状態に関わらず現在の操作履歴 JSON がクリップボードにコピーされること。
- [ ] エクスポートした JSON データを貼り付け、「リプレイ」を実行した際、設定適用から書籍表示位置までが同一セッションおよび別セッション（リロード後）で再現されること。
- [ ] 不正な JSON データ（型エラー、破損ファイル）がインポートされた際、例外が適切にキャッチされエラーメッセージが表示されること。
- [ ] XSS脆弱性対策: インポートされた書籍名（`fileName`）やコンテンツ内に `<script>` などの攻撃コードが含まれていても実行されないよう安全にエスケープ・サニタイズされること。
- [ ] 本実装は [DSN-01](../DSN-01-high_level_design.md) および [DSN-02](../DSN-02-low_level_design.md) の設計仕様と完全に一致していること（実装前に設計書を更新すること）。
- [ ] すべてのE2Eテスト (`npm run test:e2e`) およびユニットテスト (`npm run test:unit`) が正常にパスすること。
