# [REQ-04] バックログ管理簿 (Backlog Registry) - ゆうぞら (Yuzora)

本ドキュメントは、「ゆうぞら (Yuzora)」プロジェクトにおける将来の要望、未計画の機能、および改善のためのアイデア（バックログ）を記録・プールするための台帳です。

---

## 1. 目的と運用フロー (Purpose & Workflow)

### 1.1 目的
プロダクトの価値を最大化するためのロードマップや、ユーザーからの要望、技術的な改善のアイデアを漏れなく管理し、開発の優先順位付けを行うために活用します。

### 1.2 運用フロー（バックログからIssueへの昇格）
1. **バックログ登録**: 実装の可能性があるアイデアや要望を、本ドキュメントの「2. バックログ一覧」に `Draft` ステータスで追記します。
2. **要件定義・精査**: 定期的なミーティング等で要件・優先度を精査し、開発が承認されたものはステータスを `Approved` に変更します。
3. **アクティブ化（昇格）**:
   - `Approved` のアイテムから直近の開発スプリント（または着手フェーズ）で開発することが決定した際、ステータスを `Promoted` に変更します。
   - `create-issue` スキルを実行し、`docs/issues/` ディレクトリ配下に `00X-xxx.md` の形式でアクティブIssueとして起票します。
   - 紐づく Issue ID を本台帳の「関連Issue ID」に記録します。

## 3. 状態（ステータス）定義

* **Draft**: アイデアまたは初期の要望レベルであり、詳細な要件精査が行われていない状態。
* **Approved**: 要件が精査され、実装の意義が認められ、将来的に実装が予定された状態。
* **Postponed**: 検討の結果、現在のロードマップから除外され、当面は実装を見送る状態。
* **Promoted**: 開発の着手が決定し、`docs/issues/` ディレクトリにアクティブな Issue として起票された状態。
