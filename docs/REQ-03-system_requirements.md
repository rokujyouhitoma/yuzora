# [REQ-03] 要件定義書 (System Requirements Definition) - ゆうぞら (Yuzora)

## 1. はじめに (Introduction)
### 1.1 目的
本ドキュメント（要件定義書）は、要求定義書（[REQ-01-user_requirements.md](REQ-01-user_requirements.md)）で定義されたユーザー要求をシステム要件に翻訳したものです。開発プロセスにおける **TOGAF EA** の情報システムアーキテクチャおよびテクノロジーアーキテクチャの要件定義に相当します。

---

## 2. システム概要 (System Overview)
* **構成**: HTML5、Vanilla CSS、Pure JavaScriptのみで構成されるシングルページアプリケーション（SPA）。
* **動作環境**: 主要なモダンブラウザ（Chrome, Safari, Edge, Firefox等）。スマートフォンおよびPC双方に対応（レスポンシブ）。
* **対応フォーマット**:
  * 青空文庫テキストファイル（`.txt`）
  * 青空文庫XHTML/HTMLファイル（`.html`, `.xhtml`）
* **入力方法**: 以下のいずれかの方法によるファイルの読み込み・選択。
  * 事前定義された作品選択UI（マスターデータリストからの選択）
  * ドラッグ＆ドロップ（ファイルをブラウザへ直接ドロップ）
  * ファイル選択ダイアログ（ローカルファイルを指定して読み込み）
* **文字コード自動判定/デコード**:
  * 青空文庫標準の Shift_JIS (CP932) デコードを第一優先。
  * デコード失敗時は UTF-8 へのフォールバック。

## 3. 機能要件 (Functional Requirements)

### 3.1 事前定義作品の選択機能
* **マスターデータの提供**: 動作確認対象作品（吉川英治「宮本武蔵」8作品）のリストをマスターデータとしてあらかじめ保持し、起動時のウェルカム画面においてカードまたはリスト形式でユーザーに選択肢を提供する。
* **データロード方式**: 選択された作品の本文テキストデータの取得方式は、アプリ同梱の静的リソース（同梱方式）とするか、選択時に動的にフェッチ（外部取得方式）するか、基本設計にて決定し、要件としてはどちらの方式でもワンタップで読書画面へ遷移できることとする。

### 3.2 ファイル読み込みおよびデコード機能
* ドラッグ＆ドロップまたはファイル選択ダイアログから任意のファイルを入力可能とする。
* Shift_JIS からのデコードを試み、文字化け等の失敗を検知した場合は UTF-8 にフォールバックする。

### 3.3 青空文庫記法パース機能
* **ルビ（ふりがな）変換**:
  * 境界記号あり（例：`｜漢字《かんじ》` または `|漢字《かんじ》`）のパース。
  * 境界記号なし（例：連なる漢字に直接続く `漢字《かんじ》`）のパース。
* **改ページ処理**: `［＃改ページ］` を検知し、マルチカラム（ページ）の区切りとして適切にレンダリング（改ページ）。
* **傍点（強調マーク）対応**: `［＃「...」に傍点］` などの注記を検知し、傍点表示クラス（`.bouten`）を適用し、文字の右側に傍点を付与して表示。
* **不要注記のクレンジング**: 青空文庫特有のレイアウト指示注記（`［＃ここから...］`等）や制御文字を自動除去し、本文テキストのみをクリーンに表示。

### 3.4 読書画面（ビューアー）機能
* **縦書き表示と進行方向**:
  * デフォルトで日本語本来の右から左へ流れる縦書き（`writing-mode: vertical-rl`）を適用。
  * オプション設定により、左から右へ流れる縦書き（`writing-mode: vertical-lr`）へ切り替え可能。
* **初期スクロール位置の整合性**:
  * 読書画面を開いた際は、進行方向に関わらず確実に「1ページ目（RTLでは右端、LTRでは左端）」から読書が開始されること（Viewportの `direction` スタイルを動的制御する）。
* **ページ送りナビゲーション（進行方向連動）**:
  * **右から左（RTL）時**: 画面左エリアクリックまたはキーボード左矢印キーで次のページ（左方向）へ進み、画面右エリアクリックまたは右矢印キーで前のページへ戻る。
  * **左から右（LTR）時**: 画面右エリアクリックまたはキーボード右矢印キーで次のページ（右方向）へ進み、画面左エリアクリックまたは左矢印キーで前のページへ戻る。
  * **スワイプ操作（タッチデバイス）**: 画面上の左右方向へのスワイプジェスチャーを検知し、慣性で滑りすぎることなく、1回のスワイプで厳密に「1ページ分だけ」のページ切り替えを実行する。スワイプによる遷移方向は「ページの送り方向」と連動し、RTL時は右スワイプ（左から右へのスワイプ）で次のページ、左スワイプで前のページへ遷移し、LTR時は左スワイプ（右から左へのスワイプ）で次のページ、右スワイプで前のページへ遷移する。
  * **メニュー表示切替操作 (PC)**: 読書画面上でキーボードの上矢印キー（`ArrowUp`）または下矢印キー（`ArrowDown`）を押下した際、ヘッダーおよびフッターメニューの表示状態（表示/非表示）をトグル（On/Off）制御する。
* **ヘッダー/フッターUI**:
  * **ヘッダー**: 戻るボタン、本タイトル、設定ボタンに加え、**「先頭ページへ移動（最初に戻る）」ボタン**を表示。読書中はユーザー操作の停止を検知して自動非表示（3秒）。また、本文表示領域のクリック/タップによる表示/非表示（トグル）に対応。さらに、**選択した「ページの送り方向」（RTL / LTR）に応じて、先頭移動ボタンのダブルアローアイコンの向き（RTLなら右向き『>>』、LTRなら左向き『<<』）を動的に変更する。**
  * **フッター**: 読書進捗率（%）および現在のページ番号（現在ページ / 総ページ数）を表示。**ページ番号をクリックするとジャンプ入力ダイアログを表示**する。ヘッダーの表示・非表示制御と完全に同期して動作。
  * **プログレスバー**: シークバー型進捗状況バー。クリックした位置の進捗率に応じたページへジャンプする。さらに、**バー上に配置された現在位置を示すつまみ（目印）をマウスやタッチでドラッグ（スクラブ）して、リアルタイムにページ位置を切り替えることができる。進捗の増加（充填）方向およびドラッグによる進捗計算方向は「ページの送り方向」と連動し、RTL時は右端を0%・左端を100%として右から左へ進行し、LTR時は左端を0%・右端を100%として左から右へ進行する。**

### 3.5 表示カスタマイズ機能（設定引き出し）
* **テーマ（配色）切り替え**:
  * 「和紙（セピア）」（デフォルト）
  * 「明（ライトモード）」
  * 「暗（ダークモード）」
  * 「漆黒（ブラック）」
* **書体（フォント）切り替え**:
  * 明朝体（読書向けのNoto Serif JP等、適した美しいセリフ系フォント）
  * ゴシック体
* **ページの送り方向（縦書き方向）切り替え**:
  * 「右から左（標準）」
  * 「左から右」
* **文字サイズ調整**: 4段階（小、中、大、特大）
* **行間調整**: 3段階（狭い、標準、広い）
* **文字間調整**: 3段階（狭い、標準、広い）

### 3.6 状態保持機能（しおり機能）
* **自動保存（しおり）**: 最後に読んだファイルのスクロール位置（パーセンテージ）を `localStorage`（永続ストレージ）に自動記録。
* **セッション復元**: アプリ再起動時に、前回読んでいたファイル（ファイル名、ファイル種別、コンテンツ内容、スクロール位置）を自動ロード。
* **設定の永続化**: ユーザーが設定したテーマ,フォント,文字サイズ等の表示設定を `localStorage` に保存し,次回起動時に自動適用。

### 3.7 デバッグ・診断機能
* **レイアウト・見切れ診断**:
  - 表示設定（フォント,文字サイズ等）や画面・ビューポートの物理的なピクセルサイズ情報,および現在のページ番号などを取得する。
  - 現在のスクロール位置がページ境界（論理ページ幅）と合っているかを診断し,ズレ量を算出する。
  - 現在表示されているページの左右の境界線上（仕切り線）に重なっている文字（見切れている箇所）を,`Range`オブジェクトを用いてピンポイントで検出し,テキストの前後コンテキストとともに表示する。
  - これらすべての情報をMarkdown形式に整形してテキストエリアへ表示し,クリップボードにコピーできる機能を提供する。
  - 画面のスクロール干渉や縦幅超過を防ぐため,システム状態モニターとはタブで切り替えて閲覧できるUI構造とする。
  - モーダル表示開始時の位置ずれ・かくつきを防ぐために,アニメーションおよびRTL設定からの切り離し対策を施す。

### 3.8 目次表示・ジャンプ機能 (TOC)
* **見出しのパースと一意ID付与**: テキストまたは XHTML パース時、青空文庫の大・中・小見出し注記（例: `［＃大見出し］`, `［＃中見出し］`, `［＃小見出し］` 等）を自動検出し、対応する HTML 見出しタグに見出しレベル情報（レベル1: 大見出し、レベル2: 中見出し、レベル3: 小見出し）と、スクロール基準点となる一意の ID（`toc-heading-${index}`）を割り当てる。
* **クレンジングされた目次構造データの生成**: 目次ドロワー内に表示する項目テキストは、見出し文字列からルビ記号や境界文字（`《...》` や `｜`）などの装飾を完全に除去したプレーンテキスト形式で動的に抽出・保持（`currentTOC` 配列）する。
* **階層的インデントと箇条書きマーク**: ヘッダー部の目次トグルボタンにより展開されるサイド目次ドロワーにおいて、見出しのレベルに応じた視覚的インデント（レベル2: 12px, レベル3: 28px, レベル4: 44px）を付与する。さらに、中見出し（レベル3）および小見出し（レベル4）の左側には階層がわかりやすい箇条書きマーク（`•` / `◦`）を自動付与する。
* **マルチカラム座標系に対応した高精度スムーズジャンプ**: 目次ドロワーの項目をクリックした際、ページの送り方向（RTL / LTR）を判別し、スクロールコンテナおよび対象要素の `getBoundingClientRect()` から、マルチカラム境界（カラム余白 `column-gap` 等）を考慮した物理スクロール距離を正確に計算し、該当ページへとスムーズスクロール（`scrollTo`）させる。
* **ジャンプ後のフォーカス同期（アクセシビリティ）**: スクロール動作完了後に、ジャンプ先の見出し要素に対して `tabindex="-1"` と `focus({ preventScroll: true })` を非同期（ディレイ）で実行し、フォーカスを同期する（スクロール表示のブレを防ぐ）。

### 3.9 デバッグ・コマンド履歴要件
* **操作の Command オブジェクト化**: 書籍のロード、ページ移動、表示設定の変更、しおり同期などのアプリケーションの状態遷移を引き起こす主要なユーザー操作を Command パターンで抽象化する。
* **世代数制限付き履歴管理**: 最大保持数を **`100世代`** とし、上限超過時は FIFO（先入れ先出し）で古い履歴を自動破棄する。ただし、再現開始に必要な `LoadBookCommand`（書籍ロード情報）はスタック先頭（インデックス 0）に常に保護・固定して残す設計とする。
* **操作履歴シリアライズとリプレイ**: 実行されたコマンド履歴スタックを JSON 形式に相互シリアライズ可能とし、デバッグモーダルからエクスポート/インポートできるインターフェースを提供する。インポート時はディレイを挟みながらシーケンシャルに自動リプレイ実行する。

### 3.10 画面遷移状態管理フレームワーク要件 (Scene Transition Framework)
* **シーン一元管理**:
  - 画面状態の切り替えを「Initialize（初期リセット）」、「Welcome（ウェルカム）」、「Reader（読書ビューアー）」のシーンとしてカプセル化し、`SceneDirector` を介して一元管理する。
  - シーン遷移中の割り込みや二重遷移を防止するための `isTransitioning` ガードフラグを設ける。
* **UIライフサイクルとイベントクリーンアップの保証**:
  - 各シーンの進入時（`enter`）に対応するイベント登録（`setupWelcomeEvents` / `setupReaderEvents`）および初期構築（オススメ本グリッド構築等）を実行する。
  - 各シーンからの退出時（`exit`）に、その画面で登録されたすべてのイベントリスナー（ドラッグ＆ドロップ、スクロール、タッチ、リサイズ、キーボードイベントなど）の参照（管理用配列で追跡）を確実に `removeEventListener` でデタッチ（クリーンアップ）し、多重イベント登録の防止とメモリリークの解消を完全自動化する。

### 3.11 ハッシュルーティングとブラウザ履歴連動要件 (Hash Routing)
* **URLハッシュ状態の解決**:
  - `location.hash` の値（`#/welcome`、`#/reader?book=xxx`、`#/reader?local=xxx`）を監視する `Router` を導入し、URLの状態と画面の遷移・ロード状態を一方向同期させる。
  - `hashchange` イベントおよび初期ロード時に、URLハッシュに基づいて対応するシーン遷移および書籍ロードを解決する。
  - ユーザー操作（オススメ本クリック等）の遷移トリガーを直接の画面遷移指示ではなく、URLハッシュの更新に置き換える。
* **履歴および状態同期**:
  - ブラウザの「戻る」「進む」キーの操作に連動してハッシュが変更された際、ハッシュに応じた画面（ウェルカム画面 ⇔ 読書画面）が正しく同期切り替えされ、イベントの二重登録などが発生しないべき等性を保証する。
  - 推奨書籍のID（`?book=kokoro`）を含んだURLでの直接アクセス時、ウェルカム画面をスキップしてその推奨書籍が直接ロードされ読書画面が表示される（ディープリンク）ことをサポートする。
  - 起動時の自動復元セッション検出時は、URLが空またはウェルカムパスの場合に限り、自動的に `#/reader?local={fileName}` にリダイレクトして復元起動する。
  - 同一ハッシュに対する再解決ループ（ハッシュ変更 ➔ 遷移 ➔ ハッシュ同期の循環）を防止するため、ルーターと `displayBook` などの同期終端に重複遷移ガード（`currentHash` 比較判定）を設ける。

## 4. 非機能要件 (Non-Functional Requirements)

### 4.1 ユーザビリティ・デザイン (UX/UI)
* **高級感のあるデザイン**: デフォルトの和紙風テーマを含め、滑らかなアニメーション、美しく調和のとれた配色（HSL等）、フォントによるプレミアムな読書体験。
* **直感的な操作性**: マニュアルに頼ることなく直感的に使用できる操作性を重視する。ページのめくり方向、スワイプジェスチャーの挙動、キーボードのキー割り当て、プログレスバーの増加方向とドラッグ計算を「右から左（RTL）」「左から右（LTR）」の設定方向と完全に一致させ、直感的な方向感覚を損なわない操作性を保証する。
* **レスポンシブ対応 (モバイル単一カラム制限)**:
  * PC大画面では2カラム（見開き）風の最適なカラム幅（`column-width: 50vw`）を設定。
  * 画面幅の狭いモバイル端末（幅767px以下）では、表示サイズやデバイス回転に関わらず、**確実に1カラム（1段組み）のみ**でレイアウトされること（`column-width` を `calc(100vw - 左右パディング幅)` 等にし、複数カラムの並列表示を完全に排除）。
* **縦書きアライメントの最適化**:
  * 縦書きコンテンツの垂直方向の開始位置が画面下部に偏ったり二段に分割されたりしないよう、フレックスレイアウトの高さ潰れバグを回避して**常に上端に揃えて上寄せ表示**（`.reader-viewport` をブロック表示にし、`.reader-content` の高さを100%に固定）すること。
  * 親要素の `direction: rtl`（RTLスクロール位置制御用）の継承による縦書き文字のインライン進行方向の「下から上」への反転を防ぐため、`.reader-content` に `direction: ltr` を明示し、 **常に上から下へ流れる正しい日本語の縦書きフロー（および正確な行頭禁則処理・上揃え）** を保証すること。
  * 最後のページ以降に不必要にスクロールし続けたり、余計な空白・空ページが末尾に表示されるのを防ぐため、テキスト表示要素の幅を **`width: max-content` に制限し、かつパース時の末尾空行を完全にトリミング除去**すること。
* **自動レイアウト再計算**: ウィンドウサイズ変更時や表示設定（文字サイズ等）変更時に、スクロール位置（進捗率基準）を正確に再計算し、読んでいる位置を見失わないようにする。

### 4.2 セキュリティ・安全性
* **エスケープ処理**: テキスト読み込み時にHTMLタグを自動エスケープし、スクリプト実行などのXSS（クロスサイトスクリプティング）脆弱性を完全に排除して安全にレンダリングすること。

### 4.3 パフォーマンス
* **高速ロード**: 外部ライブラリへの依存を最小限にし、軽量なコード設計により静的ファイルとして一瞬で読み込みが完了する。
