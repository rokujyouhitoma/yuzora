# [FEAT] コマンド履歴デシリアライズ入力検証とコンテンツセキュリティポリシー（CSP）の導入 (ID: 043)

## 1. 概要 / Summary
「ゆうぞら」は完全なクライアントサイド静的SPAであり、操作コマンド履歴のシリアライズ・デシリアライズ、およびインポート機能（`importJSON`）を備えています。
システム設計討論（ID: 043）において、セキュリティスペシャリスト（SC）より以下のセキュリティ懸念と課題が提案されました。

1. **外部インポートによるXSS脆弱性 (T-T1: Tampering / T-E1: Elevation of Privilege)**:
   外部からインポートされるコマンド履歴 JSON ファイル内のデータ（`fileName`, `fileContent`, `targetPage` 等）が、デシリアライズおよび適用時に適切にサニタイズされていない場合、攻撃者が改ざんした履歴をインポートさせることで意図しないスクリプトがブラウザ上で実行され、XSS 攻撃が成立する危険性がある。
2. **多層防御としての Content Security Policy (CSP)**:
   リリース環境 (`compiled.html`) および開発環境 (`index.html`) において、不正なインラインスクリプトの評価や外部ドメインへのスクリプト挿入を防ぐため、厳格な CSP メタタグ設定を強制する。

これらを解消するため、本バックログでは以下を設計・実装します：
- `importJSON` 時に、パース後のオブジェクトに対してスキーマバリデーションを実施し、許可されたコマンド種別（`LoadBook`, `NavigatePage`等）および型（`string`, `number`等）以外の値が入っている場合は実行を拒否する。
- 難読化リリース用の HTML テンプレートに Content-Security-Policy の定義タグを追加する。
