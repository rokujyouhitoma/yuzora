# [FEAT] Commandパターンによるユーザー操作履歴の抽象化とデバッグ用シリアライズ対応 (ID: 012)

## 1. 概要 / Summary
バグの再現性向上、ユーザー操作の解析、および自動操作デモの実行を目的として、ユーザーが行う主要な操作（本のロード、ページめくり、表示カスタマイズ設定の変更、デバッグ操作等）を Command パターンに基づき抽象化し、実行履歴を追跡・制御します。
実行されたコマンドは時系列順に履歴リストに蓄積され、JSON 等のテキスト形式へ相互にシリアライズできるようにします。これにより、デバッグメニューから現在の操作履歴をエクスポートしたり、過去の操作ログ（JSON）を入力して一連の操作を完全に再実行・再現（リプレイ）することが可能になります。

## 3. 要件と技術的アプローチ / Requirements & Technical Approach

1. **コマンド対象スコープの限定（状態遷移の記録）**:
   低レベルのDOMイベント（マウスクリック座標、ホバー、ドロワーの開閉などの表示用インタラクション）はコマンド化から除外し、アプリケーションの「状態（State）」の更新を伴う以下の論理的操作のみをコマンド化します。
   - `LoadBookCommand`: 本のロード（ファイル名、読み込みデータ等）
   - `NavigatePageCommand`: ページ移動（先頭へ移動、シーク、進捗バー移動、次のページ/前のページ、目次ジャンプ等）
   - `UpdateConfigCommand`: 表示設定の変更（テーマ、フォント、サイズ、行間、文字間、送り方向等）
   - `SyncBookmarkCommand`: しおりの同期・リセット

2. **Command パターンによる履歴の管理**:
   - `Command` インターフェースを定義し、各具象コマンドは `execute()` およびシリアライズ用の `toJSON()`（JSONオブジェクト変換）を実装します。
   - コマンドマネージャが発行されたすべてのコマンドを履歴スタック（`commandHistory = []`）に push し、エクスポート要求時には JSON 変換を一括で行います。
   - **履歴世代数の制限**: メモリやシリアライズデータ量の肥大化を防ぐため、履歴の最大保持数は **`100世代`** に制限します。100件を超える新規コマンドが追加された場合は、最も古い操作履歴から順に自動破棄（FIFO: 先入れ先出し）します。ただし、リプレイ時の起点となる `LoadBookCommand`（書籍ロード情報）は自動破棄の対象外として、常に履歴の先頭（インデックス 0）に保護・固定して残す設計とします。

3. **リプレイ（自動再現）実行機能**:
   - デバッグ画面にシリアライズされた JSON テキストエリアを設置し、インポートされた操作ログをパースして各具象コマンドインスタンスを逆シリアライズで生成します。
   - スムーズスクロールやレンダリングの遅延を考慮するため、各コマンドを一定の時間間隔（例: `300ms` のディレイ）で非同期シーケンスとして順次再実行（`execute()`）し、ユーザー操作をリアルタイムに自動リプレイします。

## 4. 完了条件 / Success Criteria (DoD)
- [ ] ユーザーが実行した「本のロード」「表示設定の変更」「ページ遷移」が漏れなくコマンド履歴として JSON シリアライズされること。
- [ ] デバッグ画面から操作履歴の JSON データをクリップボードにエクスポートできること。
- [ ] エクスポートした JSON データを別のセッション（リロード後）でインポートした際、全く同一の書籍がロードされ、全く同じ表示設定で同じページまで自動スクロールリプレイが完了すること。
- [ ] すべてのE2Eテストおよびユニットテストが正常にパスすること。
