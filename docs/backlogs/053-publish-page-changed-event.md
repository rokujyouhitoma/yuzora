# [FEATURE] ページ移動確定後に PAGE_CHANGED イベントを発火し、それに連動してレイアウト修復をトリガーする (ID: 053)

## 1. 概要 / Summary
現在、ページ移動アニメーション（スクロール）が完了した後の処理（進捗更新、しおり保存など）は `viewer.js` の `scrollToPage()` 関数内に直接記述されており、同期的に処理されています。また、表示されるページが確定したことを伝える `YuzoraEventType.PAGE_CHANGED`（`ui:page-changed`）イベントは定義されているものの、どこからも発火されていません。

本バックログでは、ページ移動確定後に `PAGE_CHANGED` イベントを正しく発火させ、イベント駆動設計（EDA）に基づき、レイアウトの境界はみ出しチェックおよび自己修復（`adjustPageBreaksForOverrun`）をこのイベントの購読側（リスナー）でトリガーする構造へと改善します。

### SA（システムアーキテクト）との検討事項・懸念点：
1. **パフォーマンスの担保**
   - ページ移動のたびに重いレイアウト修復処理（全要素を走査して改ページを動的挿入・DOM操作する `adjustPageBreaksForOverrun`）を実行すると、ページ送りのスクロール終了時にUIのプチフリーズ（メインスレッド占有）を招く恐れがあります。
   - そのため、イベント受信時はまず軽量な読み取り専用検査（`hasOverrunNearCurrentPage`）を実行し、問題（見切れ）が検知された場合のみ実際の修復処理を走らせる仕組みを維持、あるいはさらに最適化する必要があります。
2. **依存関係の整理と疎結合化**
   - `viewer.js` のページ遷移と `renderer.js` のレイアウト修復処理を、直接の関数コールではなく `PAGE_CHANGED` イベントを介して結合することで、ビューアー制御モジュールとレンダラーモジュール間の依存関係を整理します。
