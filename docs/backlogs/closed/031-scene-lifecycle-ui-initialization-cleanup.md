# [REFACTOR] SceneライフサイクルによるUI初期化・クリーンアップ処理の定義 (ID: 031)

## 1. 概要 / Summary

現在、アプリケーション起動時や画面切り替え時に実行される以下のUI初期化およびイベント登録ロジックが、`yuzora.js` の `boot()`、`setupEventListeners()`、`setupDrawerControls()` および `ui.js` や `viewer.js` に分散しています。また、画面遷移に伴うイベントハンドラのデタッチ（クリーンアップ）ロジックが統合されておらず、メモリリークの潜在的リスクとなっています。

本バックログでは、画面表示に関係するUIイベント登録およびUI描画処理の定義場所を `Scene.enter()` / `Scene.exit()` に集約し、シーン単体で自己完結的に初期化・リソース解放を行える設計へとリファクタリングします。

---

## 2. 影響範囲と関連ファイル / Scope and Affected Files

- [MODIFY] [`scene.js`](../../src/js/modules/scene.js) — `WelcomeScene`、`ReaderScene` でのライフサイクル処理実装の追加
- [MODIFY] [`yuzora.js`](../../src/js/modules/yuzora.js) — `boot()`、`setupEventListeners()`, `setupDrawerControls()` にある初期化処理を `Scene` へ委譲
- [MODIFY] [`ui.js`](../../src/js/modules/ui.js) — 画面操作ハンドラの管理・バインド処理の Scene 連携化
- [MODIFY] [`viewer.js`](../../src/js/modules/viewer.js) — スクロールハンドラ等の登録・解除処理を `ReaderScene` にカプセル化

## 3. 要件と技術的アプローチ / Requirements & Technical Approach

### 3-1. ライフサイクル内でのイベントハンドラ管理

シーン遷移時にイベントリスナーの登録と削除を正確に一対一で行うため、イベント登録関数はデタッチ（`removeEventListener`）可能な参照として保持する必要があります。

### 3-2. `WelcomeScene` の役割
- **`enter()`**:
  - オススメ書籍（プリデファインド書籍）カードグリッドの動的生成とクリックハンドラの登録。
  - ドラッグ＆ドロップゾーン（`#drop-zone`）のドラッグオーバー/リーブ/ドロップイベント、およびファイルインプット要素の `change` イベントリスナーの登録。
- **`exit()`**:
  - オススメ書籍およびファイル入力に関わる全てのイベントリスナーを削除。

### 3-3. `ReaderScene` の役割
- **`enter(data)`**:
  - 読書ビューアー操作用のスクロールイベントリスナー（`handleScroll`）の登録。
  - ヘッダー・フッターの表示トグル監視、キーボードショートカット監視、およびドロワー制御に関わるイベントリスナーの登録。
  - 画面リサイズ監視（リフロー用オブザーバー設定）の有効化。
- **`exit()`**:
  - 上記のすべてのイベントリスナー、キーボードハンドラー、オブザーバーの解除（デタッチ）。
  - 各種ドロワーの開閉状態など、画面一時表示状態のクリーンアップ。

## 4. 完了条件 / Success Criteria (DoD)

- [ ] 各シーンに遷移した際、そのシーンに関連するDOMイベントハンドラのみがアクティブになること。
- [ ] シーンから退出した際（例: 読書画面からホームに戻る際）、登録されていた全てのイベントハンドラが漏れなく解除（`removeEventListener` 実行）されること。
- [ ] 遷移を複数回繰り返しても、イベントハンドラの多重登録やイベントの二重発火が発生しないこと（べき等性の保証）。
- [ ] ユニットテストおよびE2Eテストが全件パスすること。
