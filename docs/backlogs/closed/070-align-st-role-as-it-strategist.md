# [Refactor] Align ST Role as IT Strategist (ID: 070)

## 1. 概要 / Summary
ITストラテジスト (ST) の役割定義とドキュメント管理プロセスの見直しを行い、ビジネス戦略とITシステム（ゆうぞらプロジェクト）のトレーサビリティと整合性を向上させるためのプラン。
具体的には、STが主導する超上流工程（REQ-01 要求定義書、REQ-03 要件定義書）および受入検証プロセスの見直し、TOGAF EA (Enterprise Architecture) に基づくビジネスアーキテクチャ(BA)と他アーキテクチャ(AA/DA/TA)のアライメント強化、およびドキュメント台帳 (MNG-01) や開発プロセス定義書 (MNG-02) におけるSTの責任と権限の明確化を目的とする。

## 2. 影響範囲と関連ファイル / Scope & Affected Files
- [MNG-01 文書管理・ドキュメント台帳](../../processes/MNG-01-document_ledger.md)
  - STが担当するドキュメント（REQ-01, REQ-03等）の改定ルールおよび管理体制の見直し。
- [MNG-02 開発プロセス定義書](../../processes/MNG-02-development_process.md)
  - プロジェクト役割定義におけるSTの「ビジネス適合評価（アライメント）」および「受入検証におけるビジネス価値評価」のプロセス・基準の明文化。
  - 各開発フェーズにおけるSTの関与（HLDレビュー、受入検証の主導）をV字モデルに沿って詳細化。
- [REQ-01 要求定義書](../../requirements/REQ-01-user_requirements.md)
  - STの署名および最終評価項目の追加。
- [REQ-03 要件定義書](../../requirements/REQ-03-system_requirements.md)
  - STとSAの共同責任範囲（機能・非機能要件の策定および整合検証）の具体化。

## 3. 要件と技術的詳細 / Requirements & Technical Details
### 3.1 ビジネス・ITアライメントの強化
- TOGAFのビジネスアーキテクチャ（BA）からアプリケーション（AA）、データ（DA）、技術（TA）へのブレイクダウンにおける整合性保証。
- 要求定義（REQ-01）の「ビジネスゴール」が、システム要件（REQ-03）および基本設計（DSN-01）でどのように実現されるかのトレーサビリティ要件を明確にする。
- 要件の変更が生じた際、STがビジネスの観点から優先順位およびROIを評価するプロセスを追加。

### 3.2 開発フェーズにおけるレビューゲートの定義
- **HLD (基本設計) レビューゲート**: SAが作成した [DSN-01 基本設計書](../../designs/DSN-01-high_level_design.md) に対し、STがビジネス妥当性（ユーザー体験の直感性、ビジネス要求の充足度）を検証し、承認（Sign-off）を付与する仕組みを `MNG-02` に追加。
- **受入検証・リリースゲート**: STが受入検証（Acceptance Verification）を主導し、ビジネス要求（REQ-01）の達成度を評価するための具体的な基準（読書UX品質、パフォーマンス基準等）の明文化。

## 4. 受入基準 (DoD) / Acceptance Criteria
- [ ] `MNG-01 文書管理・ドキュメント台帳` において、ST担当ドキュメントの承認権限および改定フローが明確に定義されていること。
- [ ] `MNG-02 開発プロセス定義書` において、STの役割、HLDビジネス妥当性レビュー、および受入検証プロセスの詳細（アクター、インプット、アウトプット）が明確に更新されていること。
- [ ] V字モデルのトレーサビリティマトリクスにおいて、ビジネス要求（REQ-01）とシステム要件（REQ-03）のST主導レビュープロセスがマッピングされていること。
