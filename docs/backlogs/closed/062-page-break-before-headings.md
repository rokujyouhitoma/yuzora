# [ENH] 見出しの直前での自動改ページ機能の追加 (ID: 062)

## 1. 概要 / Summary
「見出し（大・中・小見出し）」が表示される際、その直前の要素が別の「見出し」や「ページブレイク（改ページ要素）」ではない場合に、自動的に改ページを発生させ、見出しが新しいページ（カラム）の先頭に配置されるようにするレイアウト改善機能です。

### 検討の背景
一般の書籍において、章や節の開始を示す見出しは新ページから始まるのが標準的です。現在の仕様では、見出しの直前に明示的な `［＃改ページ］` がない限り、見出しが中途半端な位置（例えばページの最下部など）に表示されてしまう場合があり、読書の視認性とレイアウト品質を高めるために、自動的に改ページを挟む機能が求められています。

## 3. 詳細要件と実装ステップ / Detailed Requirements and Implementation Steps

### 仕様定義 (SA/設計レビュー済)
1.  **自動改ページの対象**:
    *   「大見出し（`headingLevel === 2`）」および「中見出し（`headingLevel === 3`）」を対象とする。
    *   「小見出し（`headingLevel === 4`）」は、短い節が連続する書籍においてページが過度にスカスカになるのを防ぐため、自動改ページの対象外（改ページを行わない）とする。
2.  **改ページ挿入の除外条件**:
    直前の実質的な AST ノード（空行ノード `EmptyLineNode` を無視して遡ったもの）が以下のいずれかである場合、自動改ページ（`PageBreakNode`）の挿入をスキップする。
    *   見出しノード（`HeadingNode`） - 見出しが連続した際の二重改ページを防止するため。
    *   改ページノード（`PageBreakNode`） - 表紙直後や明示的な `［＃改ページ］` 直後の二重改ページを防止するため。
    *   カバーページノード（`CoverPageNode`） - 表紙直後の不要な改ページを防止するため（すでに表紙の後に1つ改ページが入っているため）。

### 実装設計
`AozoraParser.parseAozoraText` 内で、行が見出し（`isHeading === true` 且つ `headingLevel` が 2 または 3）と判定された場合：
1.  `documentChildren` 配列を末尾から逆順に走査し、最初に見つかる `EmptyLineNode` 以外のノード（直前の有効ノード）を取得する。
2.  取得したノードが存在し、かつその `type` が `'Heading'`、`'PageBreak'`、`'CoverPage'` のいずれでもない場合、`HeadingNode` をプッシュする前に `new PageBreakNode()` をプッシュする。

## 4. 受入基準 (DoD) / Acceptance Criteria (STレビュー済)
*   [ ] **基本ケース**: `本文\n［＃大見出し］` をパースした結果、HTML内に出現する `<div class="page-break"></div>` が2個（表紙後＋見出し前）であること。
*   [ ] **小見出し除外**: `本文\n［＃小見出し］` をパースした結果、見出しの前に自動改ページが挿入されず、改ページ要素が1個（表紙後のみ）であること。
*   [ ] **連続見出し**: `［＃大見出し］\n［＃中見出し］` のように見出しが連続した場合、または間に空行のみを挟む場合、中見出しの前に余分な改ページが挿入されず、改ページ要素が1個（表紙後のみ）であること。
*   [ ] **明示的改ページ直後**: `本文\n［＃改ページ］\n［＃大見出し］` のパターンで、大見出しの前に余分な自動改ページが挿入されず、改ページ要素が2個（表紙後＋明示的改ページ）のみであること。
*   [ ] すべてのユニットテストおよびE2Eテストが正常にパスすること。
