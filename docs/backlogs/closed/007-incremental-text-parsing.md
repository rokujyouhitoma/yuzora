# [FEAT] 大容量テキストのインクリメンタル（段階的）パースおよびレンダリング (ID: 007)

## 1. 概要 / Summary
大容量（1MB以上など）の青空文庫テキストを読み込む際、数万行に及ぶ全行を一括でパース・レンダリングすることで発生するメインスレッドの数秒間の完全なハングアップ（画面フリーズ）を解消します。
テキストのブロック解析・評価を一定のチャンク単位（例：500ブロックごと）にタイムスライス（`requestIdleCallback` または `setTimeout`）で非同期実行し、最初の 1 チャンク目を最速でレンダリング・表示します。残りのコンテンツはユーザーが閲覧している間に非同期でインクリメンタルに追記していくことで、初期読み込み完了までの体感速度を大幅に向上させます。

## 2. 影響範囲と関連ファイル / Scope & Affected Files
- [parser.js](../../src/js/modules/parser/parser.js) (非同期インクリメンタルパースメソッドの追加)
- [renderer.js](../../src/js/modules/ui/renderer.js) (段階的追記レンダリングメソッド `appendRender` の追加)
- [viewer.js](../../src/js/modules/ui/viewer.js) (ロード時のインクリメンタルコールバックフロー構築、キャンセルガード制御)

## 3. 要件と技術的詳細 / Requirements & Technical Details
### 3.1 タイムスライスを用いた非同期チャンクパース
- `AozoraParser` に `parseAozoraTextIncremental` メソッドを追加する。
- 500ブロック（行）処理するごとに `requestIdleCallback`（Safari等の非互換ブラウザでは `setTimeout`）を await し、UIメインスレッドの実行権限をブラウザに返還する。これにより、画面の完全なフリーズを防ぎ、スクロールや画面クリックなどのUIインタラクションを60FPSで完全に動作させ続ける。
### 3.2 段階的 HTML レンダリング
- `VerticalRenderer` に `appendRender(htmlContent)` を追加し、既存の読書ビューア DOM に新たな HTML チャンクを安全に追記する。
### 3.3 レースコンディション（読込キャンセル）の排除
- 非同期パースのループ処理内に `shouldCancel()` 判定を挟む。パース中にユーザーが別の本をロードした場合（`currentLoadId` が進んだ場合）、現在実行中のバックグラウンドループを即座に安全に中断させる。
### 3.4 最終レイアウトの自己修復
- すべてのチャンクが DOM に追記し終わった時点で、全体のレイアウト自己修復（`adjustPageBreaksForOverrun`）を1回だけ呼び出し、正確なページ境界と総ページ数を確定する。

## 4. 受入基準 (DoD) / Acceptance Criteria
- [x] 1MB超の大容量テキストをドロップまたは選択した際、1秒未満で最初のページが表示され読書可能になること。
- [x] テキスト読み込み（バックグラウンドパース進行中）の最中も、ページのめくりや設定ドロワーの開閉などのUI操作がカクつくことなくスムーズに動作すること。
- [x] バックグラウンドパース中に別の本を読み込ませた際、先行のパース処理が確実に中断され、新しい本が正しく読み込まれること。
- [x] すべての自動テストが正常に通過すること。
