# [ADR-03] GitHub Actions CI 品質ゲートの導入と GitHub Pages デプロイ統合

## 日付
2026-06-28

## ステータス
Accepted (承認済み・実装完了)

## コンテキスト (Context)
これまで、GitHub Pages への静的デプロイは `.github/workflows/static.yml` によって `main` ブランチへのプッシュ時に直接行われていた。しかし、このフローではデプロイ前に Lint、ユニットテスト、E2E テスト、および `make` による難読化・軽量化ビルド (`main-min.js` 生成) が自動実行されておらず、検証の漏れたコードが本番環境へ直接配信されるリスクがあった。

また、CI 環境やサンドボックスなどの一部のネットワーク制限された実行環境において、E2E テスト（Playwright）実行時に Google Fonts 等の外部 Web フォントリソースのロード完了待ちが発生し、テストが頻繁にタイムアウト（30秒）して CI が異常終了する課題も同時に解決する必要があった。

## 意思決定 (Decision)
1. **CI ワークフロー (`ci.yml`) の新設**:
   全ブランチへの `push` および `main` への `pull_request` を対象に、以下のステップを自動実行する CI パイプラインを新規構築する。
   - チェックアウトと Node.js 18 環境 of セットアップ
   - `npm run lint`（ESLint による複雑度 10 閾値チェックを含む静的解析）
   - `npm run test:unit`（Node.js 標準テストランナーによる単体テスト）
   - `npm run test:e2e`（Playwright によるブラウザ統合テスト）
   - `make`（Closure Compiler による `main-min.js` のビルド検証）

2. **デプロイワークフロー (`static.yml`) の CI 依存化とビルド結合**:
   - `static.yml` の直接の `push` トリガーを廃止し、`CI` ワークフローの正常完了 (`workflow_run.conclusion == 'success'`) をトリガーとする依存構成に変更する。これにより、テストと静的ビルドが正常に完了したコミットのみが本番デプロイされる「品質ゲート」を確立する。
   - デプロイの実行直前にも `make` を実行し、Closure Compiler によって最適化された `main-min.js` を確実に生成してから、`compiled.html` 等とともに GitHub Pages へデプロイ・配信する。

3. **E2E テストの外部ネットワーク通信遮断（モック）**:
   - `tests/e2e/viewer.spec.js` および `tests/e2e/diagnose.spec.js` のセットアップ処理において、外部 Web フォントリソース (`**/*.{ttf,woff,woff2,otf}`, `https://fonts.googleapis.com/**`, `https://fonts.gstatic.com/**`) に対するネットワークリクエストを Playwright の `page.route` 機能でインターセプトし、即時アボート (`route.abort()`) する設定を導入する。

## 結果・影響 (Consequences)
- **メリット**:
  - テストおよび静的解析（複雑度制限）を通過した安全なコードのみが GitHub Pages へ自動デプロイされるようになり、デリバリーの安全性が大幅に向上した。
  - 本番デプロイ時において、Closure Compiler による難読化・軽量化された `main-min.js` が自動ビルドされて含まれるようになり、配布アセットの整合性が保証された。
  - 外部 Web フォントのロード待ちを完全にブロックしたことで、E2E テスト全体の実行時間が約 1.7分 から **22秒前後へ劇的に高速化** し、ネットワーク起因のランダムなタイムアウトが解消されて CI の実行が極めて安定した。
- **注意点 / デメリット**:
  - `workflow_run` の仕様上、GitHub の仕様によりフォーク元リポジトリからのプルリクエストではデプロイが自動トリガーされない（これは本番環境保護の観点からはセキュリティ上望ましい制約である）。
  - 外部フォントがロードされない状態（ローカル明朝フォントでの代替）で E2E のスクリーンショット診断テストが走るため、フォント描画幅が環境のシステムフォントに依存する可能性がある。ただし、表示見切れテスト（DoD 基準値 15px 以上）はローカルフォント状態でも正常にパスするように調整済みである。
