# [REQ-01] 要求定義書 (User Requirements Definition) - ゆうぞら (Yuzora)

## 1. はじめに (Introduction)
### 1.1 背景 (Background)
青空文庫（ https://www.aozora.gr.jp/ ）には多くの名作小説（吉川英治「宮本武蔵」など）が公開されているが、Webブラウザでのデフォルト表示（XHTML版など）は横書きであり、小説を日本古来の縦書きで読みたい読者にとっては読みづらさを感じる課題がある。

### 1.2 目的 (Objectives)
本プロジェクト「ゆうぞら（Yuzora）」は、青空文庫のテキストおよびHTMLファイルをドラッグ＆ドロップするだけで、美しい縦書き表示に変換し、ブラウザ上で本物の本のように快適かつ**直感的な操作で**読める静的ウェブビューアーを提供する。

### 1.3 アーキテクチャドメインとの位置づけ (TOGAF EA Business Architecture)
本ドキュメント（要求定義書）は、ゆうぞらプロジェクトにおける **TOGAF EA（エンタープライズアーキテクチャ）のビジネスアーキテクチャ (BA)** の定義に相当します。ユーザーの本質的な読書プロセスや、本物の書籍に近い縦書き読書体験というビジネス価値を整理し、動作保証の対象やターゲットユーザーを規定します。

### 1.4 ビジネス要求と投資対効果 (Business Goals & TCO Optimization)
本システムは、ビジネス戦略および運用コスト（TCO）の観点から、以下の価値を最大化するよう定義されます：
* **運用コスト（TCO）の極小化**:
  一切のサーバーサイド動的処理を廃止し、完全なクライアントサイド静的SPA（Single Page Application）構成を採用することで、サーバーの維持・管理コスト、スケール時のインフラコストを実質ゼロに抑えます。これにより、ユーザー増に伴う限界費用を伴わずにサービスを永続的に提供可能な事業基盤を構築します。
* **プライバシー保護による事業差別化（事業強み）**:
  書籍データやユーザーのしおり情報をサーバーに一切送信・保持しない「ローカル完結型アーキテクチャ」を採用します。これにより、個人情報や読書履歴の漏洩リスクを根本から排除し、高度なプライバシー保護を担保された安全な電子書籍ビューアーとしてのブランド価値（競争優位性）をユーザーに提供します。

## 2. ターゲットユーザーおよび想定ユースケース (Target Users & Use Cases)
* **ターゲットユーザー**: 
  * 青空文庫で名作小説を縦書きで楽しみたい小説愛好家。
  * 電子書籍リーダーを購入せず、PCやスマートフォンのブラウザだけで手軽に縦書き読書をしたいユーザー。
* **主要ユースケース**:
  1. 青空文庫からダウンロードした小説のテキスト（`.txt`）またはXHTML（`.html`）をブラウザへドラッグ＆ドロップし、縦書き表示で読む。
  2. スマートフォンやタブレットなどで、画面上に表示された事前定義済みの作品リスト（マスターデータ）からタイトルを選択するだけで、ローカルファイルのダウンロードやファイル選択の操作を行うことなく、ワンタップで縦書きの読書を開始する。
  3. 読書途中でブラウザを閉じ、後で同じ本を開いた際に前回の位置（しおり）から読書を再開する（最初のページから本を開いた際は、確実に1ページ目から開始されること）。
  4. 部屋の明るさに合わせてテーマ（配色）を変更したり、文字サイズ・行間を調整して自分好みの表示に変えて読む。
  5. 縦書き小説の進行方向について、伝統的な「右から左（RTL）」のみでなく、現代的な「左から右（LTR）」へオプションで切り替えて読む。また、最初のページへ戻るボタンの表示（ダブルアローの向き）を読書方向（RTLなら右向き「>>」、LTRなら左向き「<<」）に動的に連動させて違和感なく操作する。
  6. 長大な作品において、最初のページ（先頭）へ戻るボタンや、任意のページ番号の指定入力、進捗状況バー上の目印（つまみ）をドラッグ（またはクリック）して直感的にページを切り替えることで、読みたいページへ瞬時に移動して読む。進捗状況バーの進行方向およびつまみの移動方向は、読書方向（RTLなら右から左へ進行、LTRなら左から右へ進行）と一致させて自然な方向感覚を提供する。
  7. 読書中に表示された上部メニュー（ヘッダー）や下部情報（フッター）を、本文表示領域をタップ（またはクリック）することで即座に非表示にし、読書に集中できるようにする。また、スマートフォンやタブレットでの横スワイプ操作時には、画面がすべりすぎず正確に「1ページ分だけ」めくられ、かつめくり動作の方向（RTLなら右スワイプで次ページ、左スワイプで前ページ；LTRなら左スワイプで次ページ、右スワイプで前ページ）を読書方向に適合させて快適に読む。

* **モバイル・レイアウトおよび配置の制約**:
  * スマートフォンなどの画面幅の狭い端末において、文章が複数段（二段など）に分割されて表示されるのを防ぎ、 **常に単一カラム（1段組み）** で表示すること。
  * 縦書きとしての自然な読みやすさを確保するため、文章の表示開始位置（縦位置）を **常に上側に揃えて（上寄せ）表示** すること。

## 3. 改ページ動作の要求定義 (Page Break Requirements)

美しい縦書きレイアウトと自然な読書プロセスを実現するため、改ページ（カラム分割）に関して以下の動作を保証すること。

*   **明示的な改ページ指定の厳守（REQ-01-PB-01）**:
    *   作品本文中に記述された青空文庫の改ページ指定（`［＃改ページ］`）は、いかなる画面サイズや表示設定（テーマ、フォント、文字サイズ、行間など）であっても、確実に次のページ（マルチカラムにおける次のカラム、または単一カラムにおける次の画面）の先頭に配置されること。
*   **見出し開始時の自動改ページおよび重複防止（REQ-01-PB-02）**:
    *   章や節の区切りを示す「大見出し」および「中見出し」は、ページの最下部に中途半端に配置されるのを防ぐため、原則として新しいページの先頭から表示が開始されること。
    *   ただし、大見出しの直後に中見出しが連続するような構造の場合、連続して改ページが発生する（大見出しと中見出しが別々のページに分断される）のを防ぎ、同一のページ内に美しく収まるようにすること。
*   **段落内の文字見切れおよびカラム跨ぎの完全防止（REQ-01-PB-03）**:
    *   1つの段落や1文字の表示が、カラムの境界線上で左右に分断（縦書きの場合は下部と上部で見切れ）されたり、重なったりして表示されるのを完全に防止すること。
    *   テキストがページの表示可能領域の高さ（段組みの境界）を越える場合は、段落全体を次のカラムへ適切に送り、スムーズな可読性を維持すること。

## 5. 今後の検討事項 (Future Roadmap)
* **複数ファイルの管理 / 本棚機能**: 過去に読み込んだファイルの履歴管理やブックマークの一覧表示。
* **目次ナビゲーション**: 長編小説における章ごとのジャンプ機能。
* **ルビ・注記の網羅性向上**: より複雑な青空文庫の外字注記や挿絵画像への対応。
